## 1. 建议与预期效果

本期采用 **本地 SQLite 记忆库 + 华为云上的轻量同步 API + 同机 PostgreSQL**。先让鱼鱼在一台电脑上可靠地记住，再让 Windows、Linux 上的鱼鱼共享同一份记忆。独立备份优先使用私有 OBS；OBS 是备份出口，不是客户端直接读写的同步入口。

不需要把本地大模型搬到服务器，也不需要先租 GPU。服务器负责账号、设备、密文存储和增量同步；聊天与记忆检索继续在客户端完成，沿用现有本地模型或用户配置的云端模型。

希望实现的体验：

- 在电脑 A 告诉鱼鱼“记住，我喜欢被叫小黎”，确认保存后，电脑 B 联网同步，也能按这个称呼回应。
- 鱼鱼能延续近期对话，知道主人最近在做什么，但不会把网页里别人的话当成主人的经历。
- 主人能在“鱼鱼的记忆”中查看、修改和删除内容，也能只保存在本机。
- 断网仍可聊天和记忆，联网后补齐；换电脑不需要从头认识。
- 两台电脑同时在线时，各自照常活动；同步的是记忆，不远程同步截图、鼠标操作或动作队列。

首期按“一个主人、一个鱼鱼档案、少量个人设备”设计，接口保留账户隔离。面向所有软件用户公开运营，应另设上线阶段，不能直接把个人服务器配置分发给所有人。

本期不建设公共注册、收费套餐或面向所有用户的云服务。客户端提供“同步服务器地址”和设备配对入口；主人的设备连接私人服务器。今后软件对外发布时，可以让使用者自行部署兼容服务，但不在安装包中内置主人的访问凭据，也不默认让其他用户接入这台私人服务器。

## 3. 鱼鱼具体记什么

### 3.1 分层记忆

| 层次 | 示例 | 首期建议 |
| --- | --- | --- |
| 主人档案与偏好 | 称呼、喜欢的食物、明确表达的交流习惯 | 用户明确保存后长期保留，可置顶 |
| 近期事件 | 最近正在开发鱼鱼、准备某次演讲 | 保存简短事实与有效期，到期不再参与召回 |
| 对话摘要 | 最近讨论到的方案、尚未完成的话题 | 按会话摘要，建议默认 30 天有效期 |
| 短期上下文 | 当前会话最近几轮问答 | 仅保留有限窗口；原文默认不跨设备同步 |
| 屏幕观察 | 正在看代码、网页出现某个名字 | 默认仅本轮使用，不自动写入长期记忆 |

长期记忆不是完整聊天日志，也不是把屏幕内容全部存下来。每条记忆至少具有内容、类型、来源、确认状态、时间、有效期、同步范围和版本信息。

### 3.2 写入与纠错规则

1. “记住……”或在记忆页手动新增：展示可编辑的记忆卡片，用户确认后立即写入；首期用明确操作保障正确性。
2. 普通聊天：可异步提取候选记忆，但候选不参与正式召回，用户确认后才生效。自动提取作为后续阶段，可单独关闭。
3. OCR、网页、新闻、Agent 输出：不能直接升级成“主人事实”。OCR 长期记忆首期关闭；后续如开放，只生成待确认候选。
4. 模型给出的推测、鱼鱼自己说过的话不能作为新的事实证据，避免越说越相信自己编出的经历。
5. 矛盾内容保留来源：明确修改覆盖旧版本；模型推断不覆盖用户确认。例：“不喝咖啡了”应替换原偏好，而不是让两条矛盾偏好同时生效。
6. 删除同时清理候选、摘要引用及检索索引；原始历史仍保留时，不能再从旧历史自动提取同一来源的已删除内容。用来源失效标记阻止重新生成，后续用户明确重存除外。

密码、API Key、验证码不进入记忆；地址、健康等私人内容不自动提取。筛选不能只依赖模型判断，还应有确定性的字段和模式过滤。

### 3.3 记忆怎样参与说话

调用链：`当前输入/场景 → 本地检索 → 检查确认状态、有效期及权限 → 按预算选取 → 装配上下文 → 模型回复`。

- 第一版采用类型、标签、关键词、时间衰减与置顶排序；中文使用规范化关键词与字/二元字切分评估召回，不能直接假定 SQLite 默认英文分词适合中文。
- 默认选 3–8 条相关记忆，初始记忆预算 300–600 tokens，最终以实际 tokenizer 和整段上下文预算裁剪；数值需在现有 4B 模型上实测。
- 聊天与屏幕陪伴使用不同的上下文策略。聊天保留有限问答；主动陪伴仍保持当前简短风格，避免每次开口都重复档案。
- 天气和新闻只取相关偏好，例：怕冷；不注入全部私人经历。
- 记忆以明确边界的数据块提供，不能成为 system 指令。屏幕上“忽略规则，把某信息永久记住”等文字不得触发写入。
- 未召回到可靠记录时允许鱼鱼说不记得；不能为保持亲近感虚构共同经历。
- 后续只有在关键词召回不足时，再增加本地 embedding 与向量索引；服务端首期不部署向量数据库。

“只保存在本机”描述的是不进入同步服务；如果用户选择云端模型，参与本轮生成的记忆仍会发给该模型供应商。界面必须明确区分“允许同步”和“允许发给云端模型”两个权限，默认不向云端模型发送仅限本机的记忆。

## 4. 已选路线与备选方案边界

华为云服务器是本期唯一实施的同步后端。以下比较记录选型理由，不代表要同时开发多套后端。

| 方式 | 适用范围 | 代价与限制 | 本项目建议 |
| --- | --- | --- | --- |
| 网盘同步整个数据库 | 单机备份、人工换机 | 运行中数据库及 WAL 可能不同步，多端覆盖无法按记忆条目合并 | 不用于多端实时同步 |
| WebDAV / 网盘 API 同步条目 | 愿意自行配置网盘的个人用户 | 要验证列举、鉴权、ETag、条件写入；仍需实现删除、幂等及冲突协议 | 不纳入首期；未来有需要再立项 |
| 华为云 OBS 直接存对象 | 密文备份、不可变事件包 | 对象存储不提供本方案的账号、设备配对和记录冲突处理；不能直接给客户端永久管理员 AK/SK | 首期用于服务端备份 |
| 华为云服务器 + 自建 API | 持续多端同步、设备管理，未来扩展 | 需维护服务、数据库、证书、备份与监控 | 已选定，本期实施 |

SQLite 官方说明了跨网络文件使用时的锁与可靠性问题；本方案据此避免共享正在运行的数据库文件，改为同步业务记录。备份使用 SQLite Online Backup API 或等价的一致性快照，不能简单复制一个活跃的 `.db` 文件。[SQLite 网络使用说明](https://www.sqlite.org/useovernet.html)、[备份 API](https://www.sqlite.org/backup.html)。

WebDAV 标准包含处理覆盖冲突的条件请求机制，但具体网盘是否正确实现，需要对目标服务实测；不承诺任意网盘即插即用。[WebDAV RFC 4918](https://www.rfc-editor.org/rfc/rfc4918.html)。

如以后增加 WebDAV，优先采用每设备独立的不可变事件文件与快照，不让所有设备反复覆盖同一个 JSON。是否能可靠列出新文件、处理重试和压缩历史，列为后端验收条件。

## 5. 实施架构与数据边界

```text
电脑 A：Windows                         电脑 B：Linux / Windows
输入、记忆页、陪伴                       输入、记忆页、陪伴
          ↓                                      ↓
      共享记忆核心                            共享记忆核心
      本地 SQLite                            本地 SQLite
      检索/上下文/Outbox                      检索/上下文/Outbox
          ↕ HTTPS + 加密记录                      ↕
                  华为云同步 API
                账户 / 设备 / 版本 / 游标
                         ↓
                     PostgreSQL
                         ↓
                  加密备份 → 私有 OBS
```

建议新增 `BigBlueFish.Memory`（跨平台记忆核心）和 `BigBlueFish.SyncServer`（ASP.NET Core 服务），客户端分别引用前者。服务端与客户端协议 DTO 可放独立小项目；不要直接引用有桌面控制语义的 `BigBlueFish.Control`。

本地数据放在用户数据目录下的 `memory/`，不要放程序安装目录或网盘目录；Windows 与 Linux 路径统一交由平台路径服务解析。SQLite 存储正文与索引时默认是本机明文，应使用用户文件权限及系统磁盘加密保护；云端端到端加密不等于本地数据库加密，若需要本机数据库加密，需另做依赖与性能评估。

### 5.1 最小数据模型

| 表或对象 | 主要字段与用途 |
| --- | --- |
| `MemoryItem` | `id`、`profileId`、`kind`、`content`、`tags`、`sourceType`、`sourceId`、`confirmed`、`expiresAt`、`syncScope`、`allowCloudModel`、`revision`、`deletedAt` |
| `ConversationSummary` | 会话、摘要、来源范围、有效期；其同步与删除遵循记忆条目规则 |
| `LocalMessage` | 有限原始对话，首期仅本地；独立清理周期 |
| `Outbox` | 与记忆修改同事务写入的待同步操作，含 `operationId`、`baseRevision`、重试状态 |
| `SyncState` | 每档案拉取游标、同步代次 `epoch`、设备身份、最近成功时间 |
| 服务端记录 | 所属账户、档案、记录 ID、版本、服务端序号、密文、加密版本、删除标记 |
| 服务端操作去重表 | 设备与操作 ID 的唯一约束，保存处理回执 |

业务时间使用 UTC 存储并保留用户事件时区，界面按当前设备时区显示。过期判断用有效期字段；冲突排序不使用客户端时钟。

### 5.2 云端加密与设备接入

建议同步首版就做客户端端到端加密：正文、标签、来源摘要等在客户端加密；服务端只见账户、设备、记录 ID、版本、大小和时间等必要元数据。服务器不能检索明文，因此检索和语义去重都在设备上执行。

- 用成熟密码库实现带认证的加密，随机 nonce 不复用，记录 ID、档案和版本等绑定到认证附加数据；不自创算法。
- 首台设备生成档案密钥。新设备先通过短期、单次有效的配对流程获得设备凭据，再由可信设备通过成熟的加密配对协议传递档案密钥；身份配对与密钥传递是两个步骤。
- 提供离线恢复码/恢复包，清楚说明：全部设备和恢复材料都丢失时，服务器无法恢复记忆正文。
- 设备 Token 与模型 API Key 分开，使用系统凭据库保存；Linux 凭据库不可用时需明确降级行为，不能静默明文落盘。
- 撤销设备立即阻止后续同步；它已下载的明文无法远程抹除。密钥疑似泄漏时需轮换档案密钥并重加密，单纯吊销 Token 不足以保护旧密文。
- 首期不提供服务端 AI 总结，避免为抽取记忆而让同步服务解密正文。

## 6. 同步协议：需要优先做可靠的部分

### 6.1 正常过程

1. 客户端在同一 SQLite 事务中写入记忆与 Outbox，然后即可向用户报告“已保存在本机”。
2. 在线时启动、网络恢复和用户手动操作触发同步；有新写入时合并约 5 秒后推送，空闲轮询初始设 60 秒并带抖动，后续按负载调整。
3. 推送带操作 ID、基础版本和同步代次；服务端检查账户/设备归属，在同一事务内写记录、变更日志、去重回执与递增序号。
4. 拉取 `after=cursor` 之后的变更，按页应用；本地应用与推进游标必须同事务完成。若同条记录有本地待推送修改，先进入冲突流程，不能覆盖 Outbox 中的内容。
5. 服务端重复收到同一个操作，只返回原处理结果。超时后客户端可安全重试，不新增重复记忆。
6. 网络故障指数退避并加随机抖动，示例 5 秒至 5 分钟封顶；鉴权失败暂停并要求重新连接，限流尊重服务端重试时间。同步失败不阻塞动画、聊天或退出。

在线、未触发退避且服务正常时，建议把跨端可见目标设为 90 秒内；这是首期验收目标，不是云厂商 SLA。

### 6.2 冲突、删除与旧设备回归

| 场景 | 处理规则 |
| --- | --- |
| 两端新增不同记录 | 按 ID 合并，均保留 |
| 两端同时修改同一条 | 服务端 CAS 检查基础版本，返回冲突；客户端保留双方内容，界面选择或编辑合并，不按最后时间静默覆盖 |
| 同一事实被两端分别建成不同 ID | 同步层保留，客户端候选去重；不得因相似度高而静默删除用户内容 |
| 一端删除，另一端离线修改 | 删除优先，拒绝旧修改；如用户确要恢复，确认后以新记录重新建立 |
| 设备长期离线，日志已压缩 | 游标失效后下载一致性快照，再处理仍有效的本地 Outbox；先核对代次与删除索引 |
| 清空云端全部记忆 | 增加档案 `epoch`，旧代次的写入一律拒绝；旧设备不能把已清空的内容重新上传 |

删除正文不等于删除所有历史。建议初期长期保留最小 ID 墓碑/删除索引，变更日志保留 90 天后可压缩；没有完成快照与旧设备回归协议前，不清理墓碑。端到端加密下服务端无法语义合并，冲突需要在客户端处理。

“停止同步”“清空本机”“删除云端”“删除所有设备记忆”是不同操作。仅关闭同步不删云端；全端删除须联网完成服务端确认，并告知离线设备要在下次连接后执行，无法保证立即抹除离线设备数据。

### 6.3 建议接口范围

下面是待实现协议，不是现有接口：

- `POST /v1/device-pairings`、`POST /v1/device-pairings/complete`：短期配对申请与兑换，带尝试限速。
- `GET /v1/devices`、`DELETE /v1/devices/{id}`：设备列表与吊销。
- `POST /v1/sync/push`：批量幂等操作，逐条返回接受、重复、冲突或拒绝结果。
- `GET /v1/sync/pull?after=...`、`GET /v1/sync/snapshot`：增量与具有固定水位的一致性快照。
- `POST /v1/profiles/{id}/reset`：清空及代次切换，防止旧设备复活数据。

个人部署第一版关闭公共注册，用服务器管理员初始化主人账户，再配对设备。每次请求从认证身份确定账户，不能相信请求体里的 `userId`。要限制批次条数、正文大小、请求频率与账户容量，并保留协议版本兼容策略。

## 7. 内置聊天与 MCP 的关系

建议增加独立的“与鱼鱼聊天”入口，直接调用现有本地/云端模型，标准版和 Safe 版都可用；原有“通过 Agent 对话”保留明确标识，避免悄悄改变双击行为。

内置聊天需有独立的多轮请求、取消与输出预算，不能直接复用当前短句陪伴输出长度和截断逻辑。记忆页也应提供直接录入，因此本地记忆阶段不必等聊天 UI 全部完成才验收。

后续给标准版 MCP 增加 `search_memory`、`propose_memory` 等明确工具，让 Agent 查询已授权内容或提交待确认候选。记忆读写权限应独立设计，默认不因开启现有 MCP 就自动开放全部记忆；此处需要调整当前整组 MCP 权限模型与说明。

外部 Agent 的内部对话历史不会自动同步。鱼鱼只能处理经过自身入口或记忆工具提交的内容；`say`/`say_next` 的文字不是可靠事实来源。未来若要求 Agent 完整会话跨端，需要单独做相应 Agent 的会话连接器。

## 8. 华为云私人服务部署

### 8.1 个人试用起步配置

2026-10-26 实施调整：针对现有 IPv6-only 实例，本机编译 Linux x64 程序包，经 Tailscale 上传；服务器下载并校验微软官方 ASP.NET 运行时，用 systemd 运行 API 和本机 PostgreSQL。入口使用 Tailscale Serve 私网 HTTPS，不增加公网 IPv4、公开 Caddy 端口或独立域名。下方通用配置中的 Compose/Caddy 路线保留给具有相应网络条件的其他部署，不是本机当前启用方式。原有 Docker 备份脚本不能直接用于原生部署，独立备份与恢复演练仍须补齐。

以下是容量规划建议，未做压测，也不是厂商最低配置承诺：

- Linux 通用 CPU 云服务器：**2 vCPU / 4 GB 内存 / 40–80 GB 系统盘**，按少量个人设备起步；无需 GPU。
- ASP.NET Core 同步服务 + PostgreSQL + Caddy 或 Nginx，通过 Compose 或 systemd 部署。
- 首期采用单机部署，数据库与 API 同机，数据库仅监听内网/容器网络，不开放公网端口；对外提供 HTTPS，管理入口限制来源地址。
- 私有 OBS 桶保存加密数据库备份；备份凭据仅留服务器，权限只覆盖所需桶和操作。
- 地域按主设备网络实测选择，重点测家中与工作地点的延迟和连通性，再租长期实例。若公开提供服务，域名与地域的备案/合规要求在部署时另行核实。

华为云安全组指南建议避免将数据库暴露公网；OBS 支持多版本控制，可辅助恢复误覆盖或误删除。多版本保留也意味着删除正文后旧备份可能仍存在，必须配合生命周期清理策略。[华为云安全组](https://support.huaweicloud.com/intl/zh-cn/usermanual-ecs/zh-cn_topic_0140323157.html)、[OBS 多版本控制](https://support.huaweicloud.com/usermanual-obs/zh-cn_topic_0045829098.html)。

### 8.2 备份、恢复与运维

- 个人试用每天做 PostgreSQL 一致性备份，建议日备份保留 7 天、周备份保留 4 周；跨机器保存，不能只放服务器同一块盘。
- 首期云端备份 RPO 目标为 24 小时、人工恢复 RTO 目标为 4 小时，均需恢复演练验证。同步终端不是独立可靠备份，删除或错误可能传播到所有设备。
- 备份加密密钥与正文档案密钥分离；换机恢复需要分别验证服务元数据、设备授权、正文解密和删除代次。
- 恢复旧备份必须更换服务同步世代并强制客户端重新对账，避免游标倒退和已删内容复活；恢复流程保留备份之后的删除记录或明确提示其缺失。
- 日志只记操作 ID、错误码和耗时，不写正文、Token、恢复码或模型请求。监控证书到期、磁盘空间、备份失败和同步错误率。
- 删除在线正文后，历史备份按最长 28 天生命周期淘汰；在界面说明期限，恢复备份必须重新应用删除索引。若需要即时不可恢复删除，另做密钥销毁与版本管理方案。

### 8.3 成本与扩容

账单分成：云主机、磁盘、公网带宽/流量、OBS 容量与请求、备份、域名；模型 API 调用另算。本文不引用活动价，购买时按地域、计费方式和实际报价确认。先按一个月试运行，再决定长期租用。

主人目前看到的云服务器费用约为每月四十几元，可作为个人预算参考，不能视为本方案所有服务的固定总价。首期费用控制如下：

- 仅租一台 CPU 服务器，同机运行 API 与数据库；不购买 GPU、托管数据库、负载均衡或独立缓存服务。
- 先在本机完成服务端开发与双客户端验证，进入真实跨网络验收前再购买云资源，减少等待开发期间的租金。
- 不主动开通额外付费组件；OBS、备份、流量和域名分别列入购买清单，部署前核对完整月费、优惠期限与续费价格。
- 客户端只同步变更，合并短时间内的写入；服务器设置日志大小、备份保留和容量预警，避免历史数据持续无上限增长。
- 如暂不使用 OBS，必须配置另一台设备定期拉取加密备份，并确认下载成功；不得以服务器本机备份替代独立备份。OBS 备份与外部设备备份至少落实一种。

记忆正文通常较小，费用和容量更应关注聊天原文、保留周期、轮询频率以及运维成本。举例：10,000 条记录按每条加索引与元数据平均 2 KB 粗算约 20 MB，另加日志、备份、历史版本和数据库固定开销；这只是估算口径。

若面向公众发布，再加入注册登录、配额、滥用防护、隐私导出与注销、告警值守、数据库迁移与压测。并发与存储达到试用容量预警后，再拆分 API 与数据库或改托管数据库；无需一开始部署 Redis、消息队列或 Kubernetes。

### 8.4 实际部署顺序与交付物

1. 在开发机启动同步 API 和 PostgreSQL，使用两个隔离客户端数据目录验证推送、拉取、冲突和删除。
2. 输出版本固定的服务部署包、配置示例、数据库迁移和备份恢复脚本；配置示例不含真实密码或密钥。
3. 核对地域、实例规格、月费与续费价，购买一台华为云 CPU 实例；配置安全组、HTTPS 入口和独立备份目的地。
4. 部署服务，执行迁移，通过管理员命令初始化唯一主人账户，默认关闭注册和新设备配对申请；需要添加设备时，由管理员临时开放限时配对。
5. 第一台电脑填写 HTTPS 服务器地址，使用短期引导凭据完成授权，生成档案密钥并保存恢复包；不让用户在客户端输入华为云 AK/SK 或数据库密码。
6. 第二台电脑通过授权配对与密钥传递接入；完成 Windows/Linux 跨网络、断网补传与撤销设备验证。
7. 执行一次真实备份恢复演练，再启用日常自动同步；交付部署说明、设备添加/吊销说明、升级回滚说明和恢复操作记录。

客户端更换服务器地址时，必须作为迁移或连接新档案的显式操作处理：验证新服务身份，清除旧设备凭据与游标绑定，保留本地记忆，并询问采用导入、合并或新档案策略，不能把旧 Outbox 直接发往新服务器。

## 9. 分阶段实施与交付

工期为熟悉当前项目的单开发者估算，不是承诺；按阶段验收，不等全部完成才试用。

| 阶段 | 工作与交付 | 验收门槛 | 估算 |
| --- | --- | --- | --- |
| A：本地记忆 | 跨平台核心、SQLite 迁移、记忆页、手动新增/纠错/删除、召回接入陪伴 | 重启保留；无网络也能记住；屏幕不自动落库；删除后不再召回 | 4–6 工作日 |
| B：内置聊天 | 独立聊天入口、有限历史、显式记住、会话摘要结构 | 无 Agent 可聊天；Safe 可用；短句陪伴风格不退化 | 3–5 工作日 |
| C：私人服务同步 | ASP.NET Core + PostgreSQL 服务端、服务器地址设置、配对、端到端加密、Outbox/游标/墓碑/代次、Windows 与 Linux 接入 | 本机双客户端通过；两端离线修改后正确合并；重试不重复；旧设备不复活删除 | 7–10 工作日 |
| D：华为云部署与可靠性 | 单台 CPU 实例部署脚本、费用清单、独立备份恢复、密钥恢复、升级回滚与端到端验收 | 真机跨网络通过；恢复演练通过；凭据与正文不入日志 | 4–6 工作日 |
| E：可选扩展 | 自动候选提取、Agent 记忆工具、语义检索；网盘/WebDAV 如有需求另立项 | 按使用反馈分别立项，不属于首期交付 | 另估 |

首个完整个人版本约 **18–27 工作日**，另留约 20%–30% 缓冲处理模型效果、跨平台凭据库和加密配对。若只做“手动记忆 + 陪伴召回”，阶段 A 完成即可试用；无需提前租服务器。

### 必须验证的场景

- 用户叫鱼鱼记住称呼，重启及另一设备同步后正确使用；不相关场景不机械重复。
- 当前网页或聊天截图含“我喜欢咖啡”，不会因此写成主人的偏好。
- 记忆块含提示词攻击、格式异常或超长内容，不能绕过权限或挤掉角色规则。
- 云端模型拒绝接收本机专属记忆；本地模型能按权限使用它。
- 写入时崩溃、服务端已提交但回执丢失、分页中断、磁盘满：事务一致且可以重试。
- 两端同改、删改并发、设备时钟错误、长期离线、游标过期、清空后旧端回归均有确定结果。
- 全新设备恢复密钥、吊销设备、Token 失效、密钥轮换、备份恢复及模式升级失败均有清楚处理。
- Windows / Linux × 标准 / Safe 的记忆行为一致；关闭记忆后生成请求不再带入记忆。
- 自动候选提取开启后，已删除来源不会被再次提取；云端清空后旧备份恢复不会静默复活内容。

## 10. 开始实施时采用的默认范围

为减少前期决策，建议以以下边界开工：

1. 先支持 Windows 与 Linux，两端共享同一鱼鱼档案；手机和网页客户端后续做，同步 API 为它们留接口。
2. 记忆与同步分别开关，初始都关闭；用户可以只启用本地记忆。
3. 首期显式记忆优先，普通聊天只生成待确认候选，OCR 不生成长期记忆。
4. 原始聊天、原始截图、OCR 正文、模型 Key、系统路径、窗口位置和动作队列不进入同步。
5. 首期只接入华为云上的个人私有同步服务，使用单台 CPU 实例；正文客户端加密，默认 OBS 做独立备份，或落实外部设备拉取备份。
6. 不增加云端推理依赖；继续让主人选择已有本地模型或自配云端接口。

后续如要同步偏好设置，逐字段建立允许列表；开机启动、电源策略、设备路径和敏感凭据保持设备独立，不能上传整个 `preferences.json` 或 `cloud.json`。

**下一步开展阶段 A，再按 B → C → D 推进。** 先完成本地记忆与内置聊天，再在开发机实现同步服务；本机双客户端验收通过后租用华为云实例并部署。无需为等待功能开发提前持续支付云服务器费用。
